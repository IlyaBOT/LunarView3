# Device profiles

`device_profiles.json` is generated by `tools/generate_profiles.py`, together with the AVR flash table `firmware/profiles.h`. JSON is UTF-8 with canonical LF endings so its SHA256 prefix matches on Windows. The host checks the 16-character hash reported by INFO before any operation. Edit the generator, regenerate both files and rebuild/reflash firmware together.

“Hardware electrically supported” means the schematic routes the required 8-bit bus, address lines and known rails through a matching adapter. It does not mean a board or adapter was tested. “Read profile verified” refers to source verification; hardware read tests are still pending. “Programming algorithm verified” is separate from both, and does not certify waveform performance. `hardware_commissioned` remains false in the manifest; firmware's deliberate `HARDWARE_COMMISSIONED` build flag is the additional runtime gate.

Bare aliases such as `2716` and `27C010` resolve to the named manufacturer profile in this table. They are conveniences, not proof that another manufacturer's part shares its algorithm or limits. Firmware commands require the canonical ASCII name; the host resolves case-insensitive aliases, including Cyrillic RF5 names.

## Fields and pin roles

Every profile records package/adapter, byte size, address/data widths, read and program rails, VPP tolerance, address/data package pin maps, CE/OE/PGM/VPP roles, pulse parameters, verification method, power sequence, source URLs and independent verification flags. Unknown programming voltages/timings are null and program_supported=false. RF5 pin maps are deliberately empty until verified; its requested capacity is present without substituting an Intel pinout.

All current enabled read profiles use 5 V and 10 us access delay. The firmware accepts a narrower 4.75-5.25 V read rail even where a datasheet permits +/-10%. It masks addresses to the selected bit count, so every unused upper address output is LOW. Status bits Q4-Q6 are preserved in each 24-bit shift.

The reference adapter sheets distinguish physical pins that change roles. Intel 2716 pin21, Intel 2764/27128A/27256 pin1 and National/Fairchild 27C010/020/040 pin1 need the specified read VPP condition, normally a tie to TARGET_VCC. **VPP_SW=0 V is not a substitute for a 5 V read VPP pin.** The NM27C512 onboard relay switches only socket pin22; it does not switch an adapter's separate VPP pin. A future write adapter needs its own suitable switching, selection and verified algorithm. Pin1 becomes A19 and pin24 OE/VPP in the 27C080 comparison, so a universal VPP-on-pin1 adapter is unsuitable.

## NM27C512 programming

The implemented source is National TL/D/10834, February 1994, pages 5-7: programming VCC 6.00-6.50 V (6.25 nominal), VPP 12.50-13.00 V (12.75 nominal), 100 us pulse and at most 25 pulses per byte, followed by byte verify. Final whole-image comparison is at 5 V. The specified programming ambient is 20-30 C; the host requires `--ambient-c`. No extra generic overprogram pulse is added. Maximum VPP is 14 V absolute, not a valid operating target. See [sources](sources.md) and [bench commissioning](bringup.md).

The entire EPROM must be erased (FF) before WRITE. The host checks exact image size before opening the port, refuses unverified algorithms and requires `PROGRAM` confirmation unless `--yes` is supplied. The default firmware is still locked even with `--yes`.

## Unsupported devices

2708 requires additional +12 V and -5 V supplies even for normal read, outside this revision's power architecture. 27C160 has a 16-bit bus, outside this 8-bit design. Other devices must not be selected through a superficially similar alias. RF5 and 080 remain explicit pending tasks, rather than silently enabled variants.
