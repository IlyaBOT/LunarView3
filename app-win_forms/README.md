# LunarView 3 — Windows Forms

Откройте **LunarView3.sln** в Microsoft Visual Studio 2022 (установленная версия 17.14), workload «Разработка классических приложений .NET». Проект C# / .NET 8 Windows Forms. Использует `System.IO.Ports 8.0.0`; при первой сборке пакет восстанавливается NuGet. На этом ПК .NET 8 Desktop Runtime уже установлен. Готовая программа после публикации находится в `release/LunarView3.exe`; запускайте её вместе со всеми файлами папки release.

Сборка: `dotnet build app-win_forms/LunarView3.sln -c Release`.
Публикация: `dotnet publish app-win_forms/LunarView3.csproj -c Release --self-contained false -o app-win_forms/release`.

## Работа

1. Запишите `../firmware/lite/build/dumper_lite.hex` в ATmega328P через ISP с корректной настройкой внешнего кварца 16 МГц. Старый код Stage 2 несовместим.
2. При снятом питании вставьте EPROM правильной стороной; для КР573РФ5 нужен адаптер.
3. Выберите COM-порт дампера и нажмите **Подключиться**. Порт всегда 115200, 8N1; кнопка меняется на **Отключиться**. Кнопка ↻ обновляет список портов. Программа отправляет CON:START, получает идентификатор и проверяет возможности Lite 2. Название, ревизия, версия, ID и дата сборки показываются внизу: информация об устройстве, разделитель и статус. Отключение отправляет CON:STOP, проверяет подтверждение и закрывает порт.
4. Выберите ROM и нажмите **Читать**. Сначала выбирается режим выводов `PINS:<profile>`, затем передаётся `READ:<size>`, данные появляются в виртуальной таблице по 16 байт на строку. Справа ASCII: печатные коды 0x20…0x7E, остальные заменяются точкой. Байты 0x80…0xFF не выдаются за ASCII.
5. Во время чтения выбор COM/ROM и все кнопки заблокированы. Форма не зависает, нижняя панель показывает «Считывание»; после проверки CRC доступно **Сохранить BIN**, статус — «Готов». При обрыве сохранение неполного дампа заблокировано, нужно подключиться заново.

Наличие FF во всём дампе само по себе не доказывает исправность чтения: пустой/неподключённый сокет также может дать FF. CRC проверяет передачу, а не электрическую исправность EPROM. Проверьте устройство на заведомо известном содержимом и повторным чтением.

## rom-chips.list

Файл находится рядом с EXE. Он копируется из проекта при сборке, поэтому редактируйте исходный `rom-chips.list`, затем собирайте/публикуйте заново, либо редактируйте файл рядом с установленным EXE. Загрузка при запуске; кодировка UTF-8, XML-фрагменты без обязательного общего корня:

```xml
<NM27C256 id="" page="1" size="32768" vcc="5.0" bus="parallel8" pins="27C256"/>
```

| Атрибут | Значение |
|---|---|
| Имя элемента | Обозначение ROM; допустимо имя XML |
| `size` | Размер ROM в байтах, положительное десятичное число |
| `page` | Десятичный размер страницы: байты для обычной памяти, слова для AVR flash; либо `SSTW` / `SSTB` |
| `pageep` | Размер страницы EEPROM AVR в байтах, десятичный |
| `sizeeep` | Размер EEPROM AVR в байтах, десятичный |
| `id` | HEX-идентификатор, пустая строка означает неизвестный; ID-команды устройству не отправляются |
| `vcc` | `3.3` или `5.0`, по умолчанию 5.0; отображение информации, питание аппаратно не переключается |
| `adapt` | Имя необходимого адаптера, например `adapter_KR573RF5` |
| `comment` | Комментарий; XML-символы экранируйте как `&amp;` / `&quot;` |
| `pins` | Режим выводов: 27C512 (по умолчанию), 27C256, 27C128; постоянные HIGH на VPP/PGM меньших ROM |
| `bus` | Дополнительный атрибут возможностей: `parallel8` для совместимых с Lite параллельных ROM; отсутствующее поле = неизвестный интерфейс |

Все перечисленные поля загружаются и сохраняются в модели записи. `page`, `pageep`, `sizeeep`, `id` — метаданные для будущих интерфейсов; режимов программирования/AVR/SST/SPI эта плата не имеет. Запись не превращает микросхему автоматически в совместимую. На текущем Lite доступно чтение только `bus="parallel8"`, 5 В, максимум 65536 байт. Напряжение в файле не регулирует питание; несовместимые записи видны в списке, но чтение для них отключено. В каталоге NM27C512 (64 КиБ), NM27C256 (32 КиБ), NM27C128 (16 КиБ) и КР573РФ5 (2 КиБ через существующий адаптер). Пример удалён. [Совместимость ROM](../docs/rom_compatibility_lite.md).

Для добавления параллельной EPROM сначала подтвердите её уровни, питание и распиновку либо изготовьте подходящий адаптер, затем укажите `bus="parallel8"`. `adapt` сообщает требование пользователю; программа не может физически определить, установлен ли адаптер. Не подставляйте значение bus ради включения неподходящей SPI/AVR-микросхемы.

## Проверки

`dotnet run --project app-win_forms/Tests/EpromDumper.Tests.csproj -c Release`: 59 проверок парсера, CRC, разбиения потока, ошибок, каталога и имитированного чтения 1/2048/32768/65536 байт.

`dotnet run --project app-win_forms/TestsUI/TestsUI.csproj -c Release`: проверки интерфейса, блокировки управления, сравнения с имитированным потоком ROM, подсветки и перехода к первому отличию, разной длины и запрета сравнения/сохранения при ошибке CRC.

Окно по умолчанию 890×690, минимальная ширина 890 пикселей, внешний отступ 4 пикселя, внутренний заголовок удалён. Нижняя панель занимает одну строку высотой 22 пикселя: информация о подключённом устройстве, разделитель и статус. Длинную информацию можно прочитать в подсказке. Статусы: «Не подключен», «Готов», «Считывание», «Ошибка подключения к программатору», «Ошибка чтения ROM», «Ошибка данных CRC» и другие ошибки операции. «Запись» и «Стирание» подготовлены для будущей полноценной версии; операций записи и стирания в LITE пока нет. После ошибки её статус сохраняется до следующего действия.

Размер ROM и открытого файла указан в байтах, кибибайтах и килобитах по 1024 бит: например, «65 536 байт (64КиБ/512КБит)» для NM27C512.

Для просмотра без подключения: `LunarView3.exe --demo`. Это явно обозначенные демонстрационные данные, не результат чтения ROM. `preview.png` получен из реально собранной формы в этом режиме.

Сборка и программные проверки выполнены. Реальный Serial/CH340, тайминги GPIO, адаптер и чтение EPROM ещё не проверялись. Контракт UART: [protocol_lite.md](../docs/protocol_lite.md).

## О программе

LunarView 3, версия **1.2**, разработчик **IB-WorkShop**, дата сборки **12.10.2026**. Цифра 3 входит в название программы; текущая версия — 1.2. Название, версия, разработчик и описание заданы в LunarView3.csproj. Дата сборки автоматически записывается в метаданные при сборке по московскому времени (UTC+3); при необходимости её можно задать параметром MSBuild BuildDate. Окно «О программе» получает эти поля из метаданных сборки.

Верхнее меню: **Файл → Открыть…** (Ctrl+O), **Сохранить BIN…** (Ctrl+S), **Выход** (Alt+F4), **Справка → О программе…** (F1). Сохранение доступно после подтверждённого чтения; меню блокируется во время операции. Логотип заменён на прозрачное изображение Lunar View Alicorn Neon Logo.png, предоставленное пользователем 12.10.2026 и встроен в EXE/DLL как ресурс из assets/LunarView_logo.png. Исходное изображение при запуске не требуется.

Для отдельного просмотра окна «О программе»: LunarView3.exe --about. about-preview.png — изображение собранного диалога.

Окно «О программе» уменьшено до 600×255 пикселей клиентской области; кнопка «Закрыть» расположена под описанием.

## Открытие и сравнение ROM — версия 1.1

**Файл → Открыть…** (Ctrl+O) загружает сырой двоичный файл .bin, .img, .rom или .dump. Байты показываются в HEX-таблице, справа печатный ASCII. Имя и размер эталона видны над таблицей. Файл можно открыть без подключения; загрузка не изменяет микросхему. Пустые файлы отклоняются; максимальный размер открываемого файла — 16 МиБ. Возможности текущего Lite по-прежнему ограничены выбранной микросхемой и 65536 байтами.

Для проверки выберите нужную микросхему, подключите дампер, откройте файл и нажмите **Сравнить**. Программа заново отправляет PINS и READ, считывает весь выбранный ROM и проверяет CRC. Сравнение выполняется только после успешного завершения передачи. Во время операции заблокированы меню, кнопки и выбор COM/микросхемы; HEX остаётся доступен для просмотра.

Если содержимое идентично, показывается соответствующее сообщение. При отличиях все отличающиеся HEX-ячейки имеют красный фон и белые цифры, включая выбранную ячейку. Курсор переходит к первому отличию, таблица прокручивается к нему. Сообщение содержит первый и последний отличающийся **байт, считанный из ROM**, и адрес в формате XX:00000000, а также общее количество отличающихся байтов.

Наведите указатель на красную ячейку: подсказка покажет точный восьмизначный HEX-адрес жирным шрифтом, затем значения из файла и ROM в HEX и двоичном виде (старший бит слева). Отличающиеся биты и соответствующие HEX-разряды выделены красным. Если размеры отличаются, все дополнительные байты тоже считаются отличиями; отсутствующее значение показано как «—», его двоичное представление — --------. Совпадение только общего префикса не считается идентичностью.

Открытый файл сохраняется отдельным эталоном, поэтому его можно сравнивать повторно. Обычная кнопка **Читать** считывает ROM без сравнения и снимает предыдущую подсветку. Новый файл тоже снимает прежний результат. При ошибке CRC или обрыве соединения успешный результат сравнения не выдаётся и непроверенный дамп сохранять нельзя; эталон остаётся загруженным.

Для демонстрации без устройства: LunarView3.exe --demo-compare (данные явно демонстрационные).
